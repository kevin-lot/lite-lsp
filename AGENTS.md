# AGENTS.md

Lite: a minimal IntelliJ plugin (Kotlin, IntelliJ Platform Gradle plugin, one Gradle module per language). The user
no longer writes code: agents do, and the IDE is only for **reading** it. The goal is to disable as many bundled
IntelliJ plugins as possible and replace them with this one light plugin.

`README.md` is the reference for features, limits, code layout and upstream credits. Read it before changing a module.

## Scope (decided, do not reopen)

- Per language: highlighting, Ctrl/Cmd+Click (go to definition, with the type inference needed to follow `a.b().c`),
  rename, Find Usages (honouring the dialog's scope). Nothing else: no completion, import management, inspections,
  formatting, run/debug or tool windows.
- Ctrl/Cmd+Click only where names actually point to each other. Many formats get highlighting alone.
- Each language module depends on `core` only. QML also depends on `typescript`, for its embedded JavaScript.
- When an official plugin is enabled alongside, Lite has won the file-type conflicts in tests. The intended setup still
  disables the official plugins (`tools/ide_diet.py`).

## Commands

```
./gradlew -q test                                    # every module
./gradlew -q :<module>:test --tests '*Name*'         # one module / test
./gradlew -q buildPlugin                             # build/distributions/lite-<version>.zip
LITE_X_CORPUS=<dir> ./gradlew -q :<module>:test --rerun --no-configuration-cache   # real-world corpus run
```

The corpus variables are listed in README › Develop, and `LITE_SHOW=1` prints the misses. Pass `--rerun`, because
environment variables are not task inputs and the run would otherwise be up to date. Reports are in
`<module>/build/test-results/test/*.xml`.

## New machine

`gradle.properties` holds machine paths: `localIdePath` (the IntelliJ IDEA Ultimate install the plugin compiles and
runs against, since nothing is downloaded), `org.gradle.java.home` and `org.gradle.java.installations.paths` (that
IDE's `jbr/`, Java 25). The system Java is a JRE without javac. To use other paths, override these keys in
`~/.gradle/gradle.properties`, which takes precedence, instead of editing the committed file.

The first build creates `.intellijPlatform/` (~4 GB, gitignored).

## Conventions

- Every change comes with tests (`<module>/src/test/kotlin`, `BasePlatformTestCase`; `<ref>`/`<def>` markers in
  resolve tests).
- A feature or language change updates, in the same change:
  - `README.md` (feature tables, limits, layout);
  - the HTML description in `src/main/resources/META-INF/plugin.xml`, grouped by feature, with the official plugin
    each row replaces;
  - the version in `build.gradle.kts` (minor for a new language or format, patch for fixes).
- A new module needs `settings.gradle.kts`, a `pluginComposedModule` in the root `build.gradle.kts`, an `xi:include`
  of `META-INF/lite-<module>.xml` in `plugin.xml`, and a test descriptor in `src/test/resources/META-INF/plugin.xml`.
- `*/src/upstream/` and the imported `.bnf`/`.flex` files are generated by `tools/import_*.py`. Never edit them by
  hand: change the script and re-run it on a fresh clone (the clone commands are in each script's docstring).
- Commits: English, Conventional Commits, only when the user asks.
- Read-only outside this repo: the user's IDE config, plugins and other projects are inspected, never changed, unless
  the user asks.

## Manual test project

`playground/` holds one small project per language and format: rust, kotlin, python, web (TS/JS),
qml, scripts (shell), docs (markdown), proto, infra (terraform/terragrunt), config, docker, styles, Makefile, ignore
files. Open `playground/` itself as the project (each part has its own manifest, and Lite keeps lookups inside it)
in the sandbox IDE (`./gradlew runIde`) or the real one, to check highlighting and navigation by hand. After a clone:
`npm install` in `playground/web` (TypeScript lib, `@types/node`). `playground/.env` is a committed fixture, not a
secret. Keep `make check` (bash -n, tsc, cargo check) passing when editing it.

## IntelliJ Platform gotchas met here

- One `Language` instance per class: give each format its own `Language` subclass. Keep registries such as
  `FMT_LANGUAGES` lazy to avoid null fields during class init.
- A secondary `LanguageFileType` has no `language` attribute in XML, and file types need distinct display names.
- `TargetElementUtil` needs a named element's `getTextOffset()` to equal its name leaf's start. Do not override it
  elsewhere, or rename fails with "element not found".
- `PsiPolyVariantReferenceBase.resolve()` returns null when there are several results, so deduplicate targets.
- `LeafElement.replaceWithText` is the simplest way to rename a token.
- In tests, the bundled CSS/JS plugins still parse HTML `<style>`/`<script>`. Test the injector's language choice
  directly.
- Kotlin: `/*` inside KDoc opens a nested comment. Escape `$` in test strings that contain templates.
